# 公开评价与客户反馈

个人 Cloudflare MCP 与 Supabase 签名反馈入口已部署，公开读取、签名校验及管理隔离均已验证。没有写入真实测试评论。

## 客户使用流程

客户在 ChatGPT 查询设施后，可要求查看评价。`get_parking_reviews` 即时请求网站现有的公开评论接口，最多20条一页，并返回是否有下一页。只有公开审核通过的内容可以返回，不读取审核队列、私有照片、作者身份或管理备注。网站人工整理的日语评价摘要必须与评论ID及当前原文匹配，否则显示原文。ChatGPT 可据此用日语概括，但必须说明本次看到的数量、时间与车种，不虚构星级、总评价数或共识。

客户想反馈时，`prepare_parking_feedback` 只取得客户愿意投稿的设施ID、车种与短评，不发送整段聊天。它生成带签名、15分钟有效的确认页链接。客户本人打开页面，检查设施与正文，勾选公开同意并点击“確認して送信”，才将评论送入现有 Supabase 的待审核队列。原审核流程批准后才会出现在网站及后续 ChatGPT 查询中。全站意见可使用 `__general__`，并选填地区。

没有直接供模型调用的投稿工具；草稿工具不写入数据，因此标记为只读预览。确认页面的提交是明确的写操作。这个设计依据 [OpenAI 工具与确认文档](https://developers.openai.com/plugins/build/mcp-server)，把预览与真正的对外提交分开。初版不接收照片、不提供审核或删除能力。

评价中“看到大型摩托停放”只是现场观察，不能覆盖设施官方的原付、排量、尺寸及费用规定。

## 服务端集成

1. 先在本任务个人目录准备一份最新个人仓库克隆，保留旧工作目录所有未提交内容。
2. 将本包放入 `integrations/chatgpt/`，执行 `node integrations/chatgpt/scripts/install-feedback-bridge.mjs <个人仓库根目录>`。脚本会检查既有生成器的关键结构，添加两个服务端模块，并让构建生成评论桥接入口；如果结构已改变，会停止而不是盲改。之后在仓库根目录运行 `node scripts/build.mjs --backend-only`。
3. 新入口为现有 Edge Function 下的 `/api/mcp-feedback`，不另建数据库。它只接受合法、未过期的签名草稿，仍通过原评论处理器执行设施校验、每小时限流、UUID去重和 pending 审核。其他路由和管理员认证流程保持原样。
4. 为这条反馈通道创建一个随机的、至少32字符的独立签名密钥，在**个人** Cloudflare Worker 和**个人** Supabase Edge Function 两侧分别保存同名 Secret：`MCP_FEEDBACK_KEY`。不要把值放入代码、公开配置、聊天、GitHub工作流或工具返回。不要使用 Supabase service_role、管理员密钥或现有 `COMMENT_HASH_SALT` 代替。
5. 密钥配置好后部署修改后的 Supabase Function 和 MCP Worker。具体账号仍只使用个人 Google/GitHub，不使用公司账号。只部署准备好的增量修改，不覆盖旧工作目录或从中进行全量发布。
6. 在 ChatGPT 中刷新 MCP 工具列表；应看到设施搜索、详情、公开评价、反馈草稿共四个工具。实际的评论提交由客户浏览器确认。

确认链接把评论草稿放在 URL 片段中，服务器收到的初始GET地址不包含正文。页面不加载第三方资源，并设置 no-referrer 和 no-store。签名密钥只存在服务端。客户浏览器确认时，将来源地址转成带密钥的假名供原有限流使用，不把原始地址送给 Supabase；不使用 ChatGPT 共享出口作为不同客户的限流身份。重试同一草稿保持同一个提交UUID。

无部署密钥时，公开评价仍可读取，但草稿工具会说明反馈配置未完成并指向网站原评论入口。密钥轮换会使旧草稿链接失效，客户可重新生成。

## 本地验证

- `node --test test/*.test.mjs`：公开字段筛选、人工摘要匹配、原文变化回退、分页、签名篡改/过期、确认来源、重复ID、待审核返回、假名身份与本地防误投稿。
- `node scripts/test-backend-feedback.mjs <隔离个人仓库根目录>`：对生成的真实 Supabase 处理器验证桥接→待审核→审核后可见、去重、限流、合并后的摩托车分类及管理员隔离。所有网络和数据库均为模拟。
- 原仓库 `node --test scripts/supabase.test.mjs`：现有评论、照片、审核与构建测试。
- 本地演示 [http://127.0.0.1:8787/demo](http://127.0.0.1:8787/demo) 可读取真实公开评价；确认提交显示“デモ…本番には送信していません”，不会向正式网站写入。

上线后仍须用本人愿意公开的真实反馈验收“提交→人工审核→网站和ChatGPT可见”。本任务没有代替客户发布任何评论。


本地页面显示更新：评价在设施卡片内自动载入；评论区沿用原网站的标题、输入框和“送信”按钮。点击发送即代表客户确认当前输入内容，同页完成提交并显示待审核提示，无需另开确认页。ChatGPT 内由模型生成的反馈草稿仍保留本人确认链接。本地发送继续为模拟，不写正式网站。
